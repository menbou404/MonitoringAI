# トレイと通知

- 対象: 段階1
- 最終更新: 2026-10-04
- 前提として読む文書: [監視コア](monitor-core.md)（実効状態と変更イベント）

ウィンドウを開いていなくても状況がわかるようにする部分。Tauri本体（`src-tauri/src/`）に置き、[監視コア](monitor-core.md)のスナップショットとイベントだけを使う。

## 1. トレイアイコン

優先度の高い順に1つを表示する。

| 状態 | アイコン | 条件 |
|---|---|---|
| 要確認 | 赤 | 未確認の `Failed` または `Orphaned` がある |
| 実行中 | 青（数字のバッジで件数を出す） | `Running` / `Queued` / `Quiet` が1件以上 |
| 完了 | 緑 | 未確認の `Completed` がある |
| 待機 | 灰色 | 上記のどれでもない |

- 「未確認」は、画面でそのジョブを表示したら解除する（[画面](window-ui.md)の `mark_seen`）。
- 未確認の情報はメモリ上にだけ持つ。本アプリを再起動したら、すでに終わっていたジョブは確認済みとみなす。
- バッジの数字は9件まで出し、それより多いときは「9+」とする。

## 2. ツールチップ

「Codex: 2件実行中（GitManager: 検証中 12分 / MonitoringAI: 編集中 3分）」のように出す。

Windowsのツールチップは文字数に上限（128文字）があるので、超える場合は「ほか N件」で省略する。

## 3. メニュー

- 実行中のジョブ（最大5件）: `ワークスペース名 — フェーズ — 経過時間`。クリックでウィンドウを開き、そのジョブの詳細を表示する
- ウィンドウを開く
- 通知: オン / オフ
- Windows起動時に起動
- （プラグインのバージョンの不一致や読み込みエラーがあるときだけ）警告の項目。クリックでウィンドウを開く
- 終了

左クリックでウィンドウを開く。経過時間などの表示は、メニューを開くときに作り直す。

## 4. 通知

Windowsのトースト通知（`tauri-plugin-notification`）を使う。[監視コア](monitor-core.md#5-公開するインターフェース)の `StateTransition` をきっかけにする。

| きっかけ | 既定 | 内容 |
|---|---|---|
| ジョブが `Running` になった | オフ | 「Codexが開始: <ワークスペース> — <依頼の先頭>」 |
| `Completed` になった | オン | 「Codexが完了: <ワークスペース> — <要約の先頭>」 |
| `Failed` になった | オン | 「Codexが失敗: <ワークスペース> — <errorMessage の先頭>」 |
| `Orphaned` になった | オン | 「Codexのジョブが停止した可能性: <ワークスペース>」 |
| `Quiet` になった | オフ | 「Codexが N 分応答していません: <ワークスペース>」 |

- 本アプリの起動時に、すでに終わっていたジョブは通知しない（`StateTransition` は最初の読み込みでは出ない）。
- 通知をクリックしたら、ウィンドウを開いてそのジョブを表示する。
- オン・オフは全体と、きっかけごとに設定できる（[アプリの土台](app-shell.md#3-設定)）。

## 5. テスト

- アイコンの選択（優先度）、ツールチップの文面と省略、通知を出すかの判定は、Tauriに依存しない純粋な関数にして単体テストする。
- 実際のトレイと通知の表示は、手動の受け入れ確認で確かめる（[DESIGN.md 7](../DESIGN.md#7-段階1の受け入れ基準)）。
