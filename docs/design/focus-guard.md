# フォーカスガード

- 対象: 段階2
- 状態: **概要のみ**。PoC（P2・P3）の結果で詳細を書く
- 最終更新: 2026-10-04
- 前提として読む文書: [データソース仕様 6. プロセスの構造](data-source.md#6-プロセスの構造)
- 関連: [ADR-0003](../adr/0003-focus-interruption-strategy.md)（3層で防ぐ方針。この機能は「受け身の防御」の層）

Codexが起動したアプリのウィンドウがフォーカスを奪ったら、取り返す機能。**AIが指示を守らなくても効く**ことが、この機能の役目である。

## 1. 概要

### Codexが起動したプロセスかの判定

- 前面に来たウィンドウのプロセスから親をたどり、`broker.json` の `pid`、または `running` のジョブの `pid` に行き着けば、Codexが起動したものとみなす。
- 親が先に終了していると、親のPIDがつながらなかったり使い回されていたりする。プロセスの作成時刻を記録した木を持ち、「親の作成時刻 < 子の作成時刻」で検証する。
- どのジョブが起動したかの対応付け: ジョブの pid の配下ならそのジョブ。ブローカーの配下なら、そのワークスペースで `running` のジョブのうち、自分の配下で app-server を動かしていないもの。

### 対処

P2の結果で決める。候補は次の3つ。
- 新しいウィンドウを最小化する
- 元のウィンドウを手前に戻す
- 別の仮想デスクトップへ移す（非公開APIのため要注意）

### 切り替えと表示

- トレイのメニューからオン・オフする。ワークスペースごとの例外も設ける。
- 取り返したら、トレイに「<ワークスペース>のCodexが起動したウィンドウを最小化しました」のように出す。

### 実装の置き場所

Win32の処理（フック、プロセスの木、ウィンドウ操作）は、新しいクレート（例: `focus-guard`）に閉じ込める。監視コアからは、ジョブの pid とブローカーの pid を受け取るだけにする。

## 2. PoC

結果は [ADR-0003](../adr/0003-focus-interruption-strategy.md) の「結果の記録」に書く。

| ID | 確かめること | 決めること |
|---|---|---|
| P2 | `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` でフォーカスの移動を検知してから、元のウィンドウに戻すまでの時間。新しいウィンドウを最小化する方法（`ShowWindow(SW_MINIMIZE)`）と、元のウィンドウを手前に戻す方法（`SetForegroundWindow`。前面ロックの制限がある）のどちらが確実か。入力中の文字が向こうに流れるか | 取る対処 |
