# 使用率とモデルの切り替え

- 対象: 段階1の追加機能
- 最終更新: 2026-10-19（第3版: 折りたたみ式・プルダウンでの選択・タブ名「ログ」）
- 前提として読む文書: [データソース仕様 3](data-source.md#3-ジョブのフィールド)、[監視コア](monitor-core.md)、[トレイと通知](tray-notification.md)、[画面](window-ui.md)、[アプリの土台](app-shell.md)

AIエージェントの使用率を表示し、使用率が高くなったら、エージェントが既定で使うモデルを軽いモデルに切り替える。手動でも切り替えられる。あわせて、各ジョブがどのモデルで動いたかを表示する。

**対象のエージェントは、今はCodexだけ。** 画面・設定・内部の型は、エージェントごとに並べられる形にしておき、後から Claude Code などを足せるようにする（[9](#9-ほかのエージェントへの広げ方)）。

## 1. 振る舞い（自動の切り替え）

| 使用率（5時間枠と週枠のうち高いほう） | Codexの既定 |
|---|---|
| しきい値（既定 90%）未満 | 基本の組み合わせ（既定 `gpt-6.1-sol`、推論の強さは変えない） |
| しきい値以上 | 節約用の組み合わせ（既定 `gpt-6-luna`、推論の強さは変えない） |

- **組み合わせ**は「モデル」と「推論の強さ」の組。推論の強さは、そのモデルが対応する値（low / medium / high など、[4](#4-モデルの一覧)）か、「変えない」を選ぶ。「変えない」なら `config.toml` の推論の強さには触らない。
- 切り替えたとき・戻したときは通知で知らせる。例: 「Codexの使用率が 92%（週枠）になったため、モデルを gpt-6-luna に切り替えました」「使用率が下がったため、モデルを gpt-6.1-sol に戻しました」。
- 切り替えるのは **Codex全体の既定**（Codexの設定ファイル `config.toml` の最上位の `model` と `model_reasoning_effort`）。Claude Code 経由のジョブも、Codexを直接使うときも、同じ既定に従う。使用率の枠はどちらも共通なので、こうする。
- `/codex:rescue --model <名前>` のようにモデルを明示したジョブは、この機能の影響を受けない。
- 動いているジョブのモデルは変わらない。変わるのは、切り替えた後に始まるスレッドからである（2026-10-16 に確認: 動いたままの `codex app-server` も、新しいスレッドを始めるときに `config.toml` を読み直す）。
- 自動の切り替えは「モデル」ページでオン・オフする（既定はオフ）。オンにするときに、Codexの設定ファイルを書き換えることを画面で明示する。

### ユーザーの変更を壊さないための決まり

- 本アプリが書き換えるのは、最上位の `model = "..."` と `model_reasoning_effort = "..."` の2行だけである。ほかの行・コメント・表（`[profiles.*]` など）はそのまま残す。行が無ければ、ファイルの先頭に足す。
- 判定は**モデルだけ**で行う（推論の強さは見ない）。
  - **節約用に切り替える**のは、現在の `model` が基本のモデルのときだけ。
  - **戻す**のは、現在の `model` が節約用のモデルで、かつ本アプリが自動で切り替えたものであるとき（記録する）だけ。
  - ユーザーが手で（または[5](#5-手動の切り替え)の手動の切り替えで）別のモデルにしていたら、自動では何もしない（記録も消す）。
- 戻すのは、両方の枠の使用率が分かっていて、どちらもしきい値未満のときだけ。
- 自動の切り替えをオフにしても、切り替え中のモデルは戻さない（オフは「以後、触らない」の意味）。
- 書き込みは、一時ファイルに書いてから置き換える。書き込む直前に読み直し、想定と違えば書かない。
- 失敗したら、通知とログに残し、5分後にもう一度試す。

## 2. 使用率の取り方

Codexは、ターンのたびに使用率を実行記録（`<CODEX_HOME>/sessions/YYYY/MM/DD/rollout-<日時>-<threadId>.jsonl`）に書く。`CODEX_HOME` の既定は `%USERPROFILE%\.codex`。

```
{"timestamp":…,"type":"event_msg","payload":{"type":"token_count", …,
  "rate_limits":{"primary":{"used_percent":1,"window_minutes":300,"resets_at":<UNIX秒>},
                 "secondary":{"used_percent":0,"window_minutes":10080,"resets_at":<UNIX秒>}, …}}}
```

- `primary` が5時間枠、`secondary` が週枠。`window_minutes` で見分け、順番には頼らない。
- 最新の実行記録（更新時刻が新しい順に5件、それぞれ末尾の128KiBまで）の**末尾から**、最後の `token_count` を探す。全体は読まない。ファイルの更新時刻と大きさが変わらなければ読み直さない。判定は5秒ごとに行う。
- `resets_at` を過ぎた枠は 0% とみなす。だから、Codexを使っていない間に枠がリセットされても、新しい記録を待たずに戻せる。
- 実行記録は、このPCでCodexを使ったときにしか更新されない。ほかの機器やWebでの使用は、次にこのPCでCodexを使うまで反映されない。これは受け入れる（より新しい値が要るなら、`codex app-server` の `account/rateLimits/read` で問い合わせられる。初めは実装しない）。
- **実行記録には会話の全文が入っている。** 読むのは `token_count` の `rate_limits` と、3の `turn_context` の決まった項目だけで、ほかの中身は保存も表示もログ出力もしない。

## 3. ジョブのモデル

- ジョブの `threadId` から実行記録のファイルを探す（ファイル名の末尾が `threadId`）。日付のディレクトリは、ジョブの `createdAt` の日付とその前後1日を探す。
- `{"type":"turn_context","payload":{"turn_id","model","effort",…}}` のうち、`turn_id` がジョブの `turnId` と一致するものを使う。`turnId` が無ければ最初のもの。同じスレッドを `--resume` で続けたジョブは、ターンごとに別の `turn_context` がある。
- 取れたモデルと推論の強さ（`effort`）を、ジョブの表示と[履歴](history.md)に加える。取れなければ、ジョブの `request.model` を使い、それも無ければ表示しない。
- `turn_context` は記録の先頭近くにあるので、ファイルの先頭から読み、見つかったら止める。

## 4. モデルの一覧

Codexは、そのアカウントで使えるモデルの一覧を `<CODEX_HOME>/models_cache.json` に保存し、自分で更新している（2026-10-18 時点で9件。うち `visibility` が `"list"` のものが7件）。

```
{ "fetched_at": "…", "client_version": "0.163.0", …,
  "models": [ { "slug": "gpt-6.1-sol", "display_name": "GPT-6.1-Sol", "description": "…",
                "default_reasoning_level": "low", "supported_reasoning_levels": [ … ],
                "visibility": "list", "priority": …, … }, … ] }
```

- 読むのは `slug`、`display_name`、`description`、`default_reasoning_level`、`supported_reasoning_levels`（各要素の `effort` と `description`）、`visibility`、`priority` だけ。ほかの項目は使わない。
- `visibility` が `"list"` のものだけを、`priority` の順に並べる。
- ファイルの更新時刻が変わったら読み直す。
- ファイルが無い・読めないときは、一覧の代わりにモデル名の入力欄を出す（今の選択は消さない）。
- 一覧に無いモデルが選ばれている（例: 一覧が変わった）ときは、その名前を「一覧に無いモデル」として表示し、選び直しを促す。

## 5. 手動の切り替え

- 「モデル」ページで、一覧からモデルと推論の強さを選び、「今すぐ既定にする」で `config.toml` に書く。書き方の決まりは1と同じ（2行だけ、直前に読み直す、一時ファイルから置き換える）。
- 手動で切り替えたら、「本アプリが自動で切り替えた」記録は消す。以後、自動の切り替えは1の決まりに従う（基本のモデルにしたなら自動の対象になり、それ以外なら自動では触らない）。
- 書く前に、確認の表示（「Codexの既定を gpt-6-luna（推論 medium）にします」）を出す。

## 6. 切り替えの履歴

- 自動・手動の切り替えを、新しい順に最大100件残す。`app_local_data_dir()/model-switch-history.json`。
- 1件の中身: 日時、エージェント（`codex`）、きっかけ（自動で節約用へ / 自動で戻す / 手動）、前後のモデルと推論の強さ、そのときの使用率（5時間枠・週枠）。
- 書き込みに失敗しても、切り替え自体は取り消さない（ログに残す）。

## 7. 表示

### 「モデル」ページ

ウィンドウ上部の切り替えは「**実行中**」「**ログ**」（旧「すべて」）「**モデル**」の3つにする。ページの中は、エージェントごとのまとまりを縦に並べる。今はCodexのまとまりだけを出す。

**ページ全体がスクロールしない**ことを目標にする（ウィンドウの最小の大きさ 720×480 でも）。そのために、詳しい操作は折りたたみ、**閉じていても、いま何が設定されているかが1行で分かる**ようにする。文言は短くし、長い注意書きは「？」の中に入れる。

Codexのまとまりの中身（上から）:

1. **要約の行**（常に表示）: 使用率（「5時間 17%（14:30 にリセット）」「週 3%（10/22 09:00 にリセット）」。小さな横棒つき。しきい値を超えた枠は強調。分からないときは「記録なし」）と、現在の既定（「GPT-6.1-Sol · high」。自動で節約用に切り替え中なら「節約中」の印）。
2. **折りたたみの欄**を3つ。開けるのは一度に1つだけ。
   | 欄 | 閉じているときの1行（例） | 開いたときの中身 |
   |---|---|---|
   | 手動の切り替え | 今: GPT-6.1-Sol · high | モデルと推論の強さを選び、「今すぐ既定にする」（[5](#5-手動の切り替え)） |
   | 自動の切り替え | オン · 90%以上で GPT-6.1-Sol(high) → GPT-6-Luna(変えない) | オン・オフ、しきい値、基本の組み合わせ、節約用の組み合わせ、「保存」 |
   | 切り替えの履歴 | 最新: 10/18 20:30 手動で GPT-6-Luna へ（全3件） | [6](#6-切り替えの履歴) を新しい順に。欄の中だけでスクロールする |

**選び方**:
- モデルは**プルダウン（選択欄）**で選ぶ。選択肢は一覧の表示名。選んだモデルの説明だけを、選択欄の下に小さく1行で出す。
- 推論の強さも**プルダウン**で選ぶ。選択肢は「変えない」と、選んだモデルが対応する値。**選んだモデルが推論の強さに対応していない（`supported_reasoning_levels` が空）ときや、一覧に無いモデルのときは、推論の強さの欄を選べない状態にする**（値は「変えない」に固定）。
- 基本と節約用に同じモデルは選べない（もう一方で選んでいるモデルは選択肢で選べない状態にする）。
- 一覧が取れないときだけ、モデル名の入力欄にする。

### ほかの場所

- **画面の上部**（どのページでも）: 「5時間 42%・週 18%」と現在の既定のモデルを小さく出す（今のまま）。押すと「モデル」ページを開く。
- **ジョブ**: 実行中のカード、一覧、詳細に、モデル名（と推論の強さ）を出す（今のまま）。
- **トレイ**: ツールチップに使用率と既定のモデルを1行で加える（今のまま）。
- **設定（⚙）**: モデル切り替えの欄は「モデル」ページへ移したので、設定からは外す。

## 8. 設定

エージェントごとに持つ。今は `codex` だけ。

```
"agents": { "codex": {
  "autoSwitch": false, "threshold": 90,
  "base":  { "model": "gpt-6.1-sol", "effort": null },
  "saver": { "model": "gpt-6-luna",  "effort": null },
  "switchedByApp": false } }
```

- `effort` が `null` なら「変えない」。
- 第1版の平らな項目（`autoModelSwitch`、`modelSwitchThreshold`、`baseModel`、`saverModel`、`modelSwitchedByApp`）が設定ファイルにあれば、読み込むときに `agents.codex` へ移し、次に保存するときに平らな項目は消す。

## 9. ほかのエージェントへの広げ方

- 内部では、エージェントごとに「使用率を読む」「現在の既定を読む」「使えるモデルの一覧を読む」「既定を書く」を持つ形にする。今はCodexだけを実装する。
- 次の候補は Claude Code（使用率、サブエージェントなど）。データの取り方は別に調べ、別の文書で決める。対応するまでは、ページにも出さない。

## 10. 実装の置き場所

- 実行記録を読む処理（使用率、ジョブのモデル）と、`models_cache.json` を読む処理は `monitor-core` に置く。`CODEX_HOME` は本アプリから渡す。テストでは一時ディレクトリを渡す。
- `config.toml` の書き換えは、最上位の文字列の値を読み書きする関数（キーを引数にとる）として `monitor-core` に置き、単体テストで確かめる。新しいクレートは足さない。
- 判定（しきい値、切り替え・戻し）、手動の切り替え、履歴、通知は本アプリ側に置く。

## 11. テスト

- 使用率: 実行記録の末尾の `token_count` を読む。枠を `window_minutes` で見分ける。`resets_at` を過ぎた枠を 0% にする。途中で切れた行・壊れた行を飛ばす。
- モデル: `turn_id` で正しい `turn_context` を選ぶ。記録が無いときは `request.model` に戻る。
- 一覧: `visibility` で絞り、`priority` で並べる。決まった項目以外を持ち出さない。ファイルが無い・壊れているとき。
- 設定ファイルの書き換え: `model` と `model_reasoning_effort` の置き換え、行が無いときの追加、「変えない」のときに推論の強さに触らない、表の中（`[profiles.x]` の下）には触らない、コメントや改行コードを保つ。
- 判定: しきい値の前後、両方の枠、ユーザーが手でモデルを変えていたときに何もしないこと、手動の切り替えで記録が消えること。
- 設定の移行: 第1版の平らな項目から `agents.codex` へ。
- 履歴: 100件で古いものから消える。壊れたファイルを読めなくても起動を止めない。
