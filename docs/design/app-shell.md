# アプリの土台

- 対象: 段階1（段階2・3でも共通）
- 最終更新: 2026-10-08
- 関連: [ADR-0001](../adr/0001-app-framework.md)（Tauriを選んだ理由とメモリの方針）

常駐の仕組み、ウィンドウの寿命、設定、多重起動の防止、ログなど、機能を支える部分。Tauri本体（`src-tauri/src/`）に置く。

- アプリ名: **MonitoringAI**
- アプリID（Tauriの `identifier`）: **`com.menbou404.monitoringai`**

## 1. 常駐

- 起動時はウィンドウを開かず、トレイだけを出す（`tauri.conf.json` の `app.windows` は空）。
- ウィンドウが1つも無い状態でも動き続ける。Tauri 2 の `RunEvent::ExitRequested { code, api }` で、**`code` が `None`（最後のウィンドウが閉じられた）のときだけ** `api.prevent_exit()` を呼ぶ。
- 終了するのは、トレイのメニューの「終了」を選んだときだけとする。「終了」では `app.exit(0)` を呼ぶ（このとき `code` は `Some(0)` なので止めない）。

## 2. ウィンドウの寿命

- **ウィンドウは閉じたら破棄し、開くたびに作り直す。** 隠すだけにすると WebView2 のプロセスがメモリに残り続け、Tauriを選んだ利点がなくなる（[ADR-0001](../adr/0001-app-framework.md)）。閉じる操作（`CloseRequested`）は横取りしない。
- ウィンドウは `WebviewWindowBuilder` でラベル `main`、URL `index.html`、タイトル「MonitoringAI」で作る。既定の大きさは 1000×700、最小は 720×480。
- すでに開いているときに「開く」操作をしたら、最小化を解いて手前に出す。
- トレイから特定のジョブを指定して開く流れは[画面 3](window-ui.md#3-イベントrust--画面)のとおり（表示待ちのジョブを記録し、新しいウィンドウは `take_pending_focus` で取り出す）。
- ウィンドウの位置と大きさは、閉じるときに設定に保存し、次に開いたときに復元する。保存した位置が今の画面の外にあるときは、既定の位置（画面中央）に戻す。
- ウィンドウを開けなかったとき（WebView2 ランタイムが無い場合など）は、ログに記録し、トレイのメニューの警告の項目に「ウィンドウを開けませんでした」と出す。トレイと通知は、WebView2が無くても動く。

## 3. 設定

保存先: Tauri の `app_config_dir()`（Windowsでは `%APPDATA%\com.menbou404.monitoringai\`）の `settings.json`。

| 項目 | 既定値 |
|---|---|
| 通知のオン・オフ（全体と、きっかけごと） | [トレイと通知 4](tray-notification.md#4-通知)のとおり |
| `Quiet` と判定するまでの分数 | 10 |
| 一覧に出す終わったジョブの期間（日） | 3 |
| 履歴の保存期間（日） | 30（[履歴 4](history.md#4-保存期間)） |
| 追加で監視する状態ルート | なし |
| Windows起動時に起動 | オフ（`tauri-plugin-autostart`） |
| ウィンドウの位置と大きさ | なし |

- 知らない項目は無視し、足りない項目は既定値で補う（将来の項目追加に備える。2026-10-09 に「最近」の時間と件数を、一覧の期間（日）と履歴の保存期間（日）に置き換えた。古い項目は無視してよい）。
- 設定ファイルが壊れていたら既定値で起動し、壊れたファイルは `settings.json.bak` に退避する。
- 保存は一時ファイルに書いてから置き換える（書き込み途中で落ちても壊れないように）。
- 設定を変えたら、[監視コア](monitor-core.md#5-公開するインターフェース)の `update_config` で反映する。再起動は不要にする。
- 「Windows起動時に起動」は、自動起動プラグインの実際の状態を正とする。メニューで切り替えたら、プラグインで有効・無効にしてから設定に保存する。

## 4. 多重起動の防止

`tauri-plugin-single-instance` を使う。**他のプラグインより先に登録する。** 2つ目を起動したら、1つ目のウィンドウを開く。

## 5. 監視コアとのつなぎ方

- 起動時に `Monitor::start` を呼び、`Monitor` と、本アプリの状態（設定、未確認の集合、直近のスナップショット）をまとめて Tauri の管理状態（`app.manage`）に入れる。
- `Receiver<MonitorEvent>` は専用のスレッドで受け取る。受け取ったら、未確認の集合と直近のスナップショットを更新し、トレイ・通知に反映する。ウィンドウがあれば画面にもイベントを送る（画面の段階で使う）。
- 1分ごとのトレイの作り直し（[トレイと通知 3](tray-notification.md#3-メニュー)）も、このスレッドで行ってよい（`recv_timeout` を使う）。
- 画面向けのコマンドとイベントは[画面 2・3](window-ui.md#2-コマンド画面--rust)に定める。未確認の集合・表示待ちのジョブ・ログの購読先は本アプリの状態（`state.rs`）に置き、トレイと画面の両方から同じ関数で操作する。

## 6. 本アプリのログ

- Tauri の `app_log_dir()`（Windowsでは `%LOCALAPPDATA%\com.menbou404.monitoringai\logs\`）に出す。`tracing-appender` で日ごとに分け、7日分を残す。
- 開発ビルドでは標準エラー出力にも出す。出す量は環境変数 `RUST_LOG` で変えられるようにする（既定は `info`）。
- 依頼の内容やCodexのログの本文は書き出さない（IDと件数まで）。

## 7. ファイル構成（目安）

```
src-tauri/src/
├─ main.rs           起動するだけ
├─ lib.rs            Builder の組み立て、プラグインの登録、RunEvent の処理
├─ state.rs          本アプリの状態（設定、未確認の集合、直近のスナップショット）
├─ bridge.rs         監視コアのイベントを受け取るスレッド
├─ presentation.rs   表示を決める純粋な関数（トレイと通知 5）
├─ tray.rs           トレイアイコンとメニュー
├─ notify.rs         通知
├─ window.rs         ウィンドウの作成・復元・位置の保存
├─ settings.rs       設定の読み書き
└─ logging.rs        ログの初期化
```

## 8. テスト

- 設定の読み書き（既定値での補い、知らない項目、壊れたファイルの退避、一時ファイル経由の保存）を `tempfile` で単体テストする。
- ウィンドウの位置が画面の外にあるかの判定は、純粋な関数にして単体テストする。
- 常駐、ウィンドウの寿命、多重起動の防止、自動起動は、手動の受け入れ確認で確かめる（[DESIGN.md 7](../DESIGN.md#7-段階1の受け入れ基準)）。
