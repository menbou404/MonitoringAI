# アプリの土台

- 対象: 段階1（段階2・3でも共通）
- 最終更新: 2026-10-04
- 関連: [ADR-0001](../adr/0001-app-framework.md)（Tauriを選んだ理由とメモリの方針）

常駐の仕組み、ウィンドウの寿命、設定、多重起動の防止、ログなど、機能を支える部分。Tauri本体（`src-tauri/src/`）に置く。

## 1. 常駐

- ウィンドウが1つも無い状態でも動き続ける。Tauri 2 では `RunEvent::ExitRequested` で `api.prevent_exit()` を呼ぶ。
- 終了するのは、トレイのメニューの「終了」を選んだときだけとする。
- 起動時はウィンドウを開かず、トレイだけを出す。

## 2. ウィンドウの寿命

- **ウィンドウは閉じたら破棄し、開くたびに作り直す。** 隠すだけにすると WebView2 のプロセスがメモリに残り続け、Tauriを選んだ利点がなくなる（[ADR-0001](../adr/0001-app-framework.md)）。
- すでに開いているときに「開く」操作をしたら、手前に出す。
- トレイや通知から特定のジョブを指定して開いたときは、画面の準備ができてから `focus-job` イベントを送る（[画面 3](window-ui.md#3-イベントrust--画面)）。
- ウィンドウの位置と大きさは覚えておき、次に開いたときに復元する。

## 3. 設定

`%APPDATA%\<アプリID>\settings.json` に保存する。

| 項目 | 既定値 |
|---|---|
| 通知のオン・オフ（全体と、きっかけごと） | [トレイと通知 4](tray-notification.md#4-通知)のとおり |
| `Quiet` と判定するまでの分数 | 10 |
| 「最近」に表示する期間と件数 | 24時間、50件 |
| 追加で監視する状態ルート | なし |
| Windows起動時に起動 | オフ（`tauri-plugin-autostart`） |
| ウィンドウの位置と大きさ | なし |

- 設定ファイルが壊れていたら既定値で起動し、壊れたファイルは `settings.json.bak` に退避する。
- 設定を変えたら、[監視コア](monitor-core.md#5-公開するインターフェース)の `update_config` で反映する。再起動は不要にする。

## 4. 多重起動の防止

`tauri-plugin-single-instance` を使う。2つ目を起動したら、1つ目のウィンドウを開く。

## 5. 本アプリのログ

- `%LOCALAPPDATA%\<アプリID>\logs\` に出す（`tracing`）。日ごとに分け、7日分を残す。
- 依頼の内容やCodexのログの本文は書き出さない（IDと件数まで）。

## 6. WebView2が無い場合

WebView2 ランタイムが無い、または無効にされている環境では、ウィンドウを開くときにメッセージボックスで案内を出す。トレイと通知は、WebView2が無くても動く。

## 7. テスト

設定の読み書き（壊れたファイルの扱いを含む）を単体テストする。常駐、ウィンドウの寿命、多重起動の防止は、手動の受け入れ確認で確かめる（[DESIGN.md 7](../DESIGN.md#7-段階1の受け入れ基準)）。
