# 画面とRust・画面間のやり取り

- 対象: 段階1
- 最終更新: 2026-10-04
- 前提として読む文書: [監視コア](monitor-core.md)、[データソース仕様](data-source.md)

ジョブの一覧と詳細を見る画面（React + TypeScript + Vite、`src/`）と、Rustとのやり取りの取り決め。ウィンドウの作成と破棄は[アプリの土台](app-shell.md#2-ウィンドウの寿命)を参照。

## 1. 画面の構成

1つのウィンドウを左右に分ける。画面の言語は日本語とする。ライト／ダークテーマはOSの設定に従う。

### 左: ジョブ一覧

- 「実行中」と「最近」の2つのグループに分ける。「最近」は24時間以内のジョブで、件数は設定で変えられる。
- 各行の内容: 状態アイコン、ワークスペース名、種別（`kindLabel`）、依頼の先頭（1行）、フェーズ、経過時間（または終了時刻）。
- ワークスペースで絞り込める。
- 一覧が長くなるので、仮想スクロールのライブラリを1つ使う。

### 右: 詳細

- 見出し: ワークスペース名、種別、状態、開始時刻・経過時間、書き込みの許可（`write`）。
- 依頼の全文（折りたたみ式）。取り方は[データソース仕様 3](data-source.md#3-ジョブのフィールド)のとおり。
- **ログ**: リアルタイムで追記し、末尾にいる間は自動でスクロールする。
  - `Running command:` の行は等幅で表示する。
  - `Assistant message` と `Final output` のブロックは目立たせる。
  - 最初は末尾の 1MB だけを表示し、それより前は「さらに読み込む」ボタンで読む。
- 結果: 完了したら `state.json` 側の `summary` を表示する。ジョブファイルの `rendered` があれば、それも表示する。
- 操作: 「ワークスペースのフォルダを開く」「ログファイルを開く」「IDをコピー」（ジョブID / threadId）。
- 詳細を開いたら `mark_seen` を呼ぶ。

### 上部のバナー

未確認のプラグインのバージョンや読み込みエラーを出す（`get_health` / `health-changed`）。

## 2. コマンド（画面 → Rust）

| 名前 | 引数 | 戻り値 |
|---|---|---|
| `list_jobs` | なし | `JobSummary[]`（実効状態を含む） |
| `get_job` | `id` | `JobDetail`（ジョブファイルを読み足したもの） |
| `read_log` | `id`, `from`（バイト位置。省略すると末尾から1MB） | `{ text, start, end, truncatedBefore }` |
| `subscribe_log` / `unsubscribe_log` | `id` | なし。詳細を開いたとき・閉じたときに呼ぶ |
| `mark_seen` | `id` | なし |
| `open_path` | `kind`（`workspace` / `log`）, `id` | なし |
| `get_settings` / `set_settings` | 設定 | 設定 |
| `get_health` | なし | プラグインのバージョン、監視中の状態ルート、直近のエラー |

`open_path` は、**本アプリが把握しているジョブのパスだけ**を開く。画面から任意のパスを受け取らない。

## 3. イベント（Rust → 画面）

| 名前 | 内容 |
|---|---|
| `jobs-changed` | 変更されたジョブ（`JobSummary[]`）と削除されたID |
| `log-appended` | `{ id, text, start, end }`。購読中のジョブだけに送る |
| `health-changed` | `get_health` と同じ内容 |
| `focus-job` | `{ id }`。トレイのメニューや通知から開かれたときに、表示するジョブを指定する |

ウィンドウは開くたびに作り直されるので、画面は起動時に必ず `list_jobs` と `get_health` で全体を取り直す。

## 4. 型

`JobSummary` / `JobDetail` などの型はRust側で定義し、TypeScriptの型を自動生成する（`ts-rs` など）。手で二重に書かない。

## 5. テスト

- Vitestで、表示用の変換（フェーズ名、経過時間、ログの区切りと色分け）を試す。
- Rust側のコマンドは、薄いラッパーにとどめ、中身は[監視コア](monitor-core.md)のテストで確かめる。
