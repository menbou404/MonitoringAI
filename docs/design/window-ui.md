# 画面とRust・画面間のやり取り

- 対象: 段階1
- 最終更新: 2026-10-11（実行中の画面をフォルダごとのタイルに変更）
- 前提として読む文書: [監視コア](monitor-core.md)、[データソース仕様](data-source.md)、[ジョブの文脈](job-context.md)、[履歴](history.md)、[アプリの土台](app-shell.md)、[トレイと通知](tray-notification.md)
- 前提: Codexのジョブは、**同じワークスペースでも別のワークスペースでも、複数が同時に動く**。一覧も詳細も、同時に何件動いていても見分けられるようにする。

ジョブの一覧と詳細を見る画面（React + TypeScript + Vite、`src/`）と、Rustとのやり取りの取り決め。ウィンドウの作成と破棄は[アプリの土台 2](app-shell.md#2-ウィンドウの寿命)を参照。

## 1. 画面の構成

ウィンドウには**2つの画面**があり、上部の切り替え（`実行中 N` ／ `すべて`）で移る。画面の言語は日本語。ライト／ダークテーマはOSの設定に従う（`prefers-color-scheme`）。

| 画面 | 目的 | 中身 |
|---|---|---|
| **実行中**（[1.1](#11-実行中の画面)） | いま何が動いているかを見渡す | 動いているジョブのカードだけ。ログは出さない |
| **すべて**（[1.2](#12-ジョブ一覧すべての左)〜[1.3](#13-詳細すべての右)） | 終わったジョブも含めて調べる | 左に圧縮した一覧、右に詳細とログ |

- **ウィンドウを開いたときは、常に「実行中」から始める。** ただし、トレイのメニューで特定のジョブを選んで開いたとき（[3](#3-イベントrust--画面)の `take_pending_focus` / `focus-job`）は、「すべて」でそのジョブを開く。
- 切り替えの `実行中 N` の N は、実効状態が `Queued` / `Running` / `Quiet` / `Orphaned` のジョブの件数。
- 上部には、切り替えのほかに、ワークスペースの絞り込み（「すべて」のときだけ）と設定ボタン（⚙）を置く。バナー（[1.4](#14-上部のバナー)）は両方の画面で出す。

### 1.1 実行中の画面

動いているジョブ（実効状態が `Queued` / `Running` / `Quiet` / `Orphaned`）だけを、**フォルダ（ワークスペース）ごとに分けて、小さなカードのタイル**で並べる。**ログは出さない。** 「いま何が動いていて、本当に進んでいるか」を一目で見るための画面。

```
[実行中 5 | すべて]                                   ⚙
📁 FakeWork  実行中 3
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│大きなリファクタ…│ │段階4: elicita…│ │ログ表示の仮想…│
│名前のない会話  │ │名前のない会話  │ │名前のない会話  │
│[応答なし？]42分│ │[編集中] 13分   │ │[調査中] 4分    │
│ ·動き12分前    │ │ ·動き2秒前     │ │ ·動き1秒前     │
│cargo build …  │ │Applying 3 …   │ │Searching: …   │
└──────────────┘ └──────────────┘ └──────────────┘
📁 GitManager  実行中 2
┌──────────────┐ ┌──────────────┐
│Codexに段階4を…│ │READMEの誤字修正│
│ …             │ │ …             │
└──────────────┘ └──────────────┘
直近の完了: Codexに画面の実装を依頼（14:37） · ほか 17件
```

- **フォルダごとのまとまり**: 1つのフォルダの見出しとカードを、1つの「まとまり」（薄い枠で囲んだ区画）にする。
  - **まとまりは横に並べる。** 画面に余裕があれば、FakeWork のまとまりの右に OtherWork のまとまりを置き、収まらなければ次の段に回す（`display: flex; flex-wrap: wrap`）。
  - まとまりの幅は、中のカードの枚数で決める: `min(カードの枚数, 3)` 列分（1列はカード1枚分の約260px と間隔）。画面の幅がそれより狭ければ画面の幅に合わせる。4枚以上のカードは、3列で折り返して段を増やす。
- **フォルダの見出し**: フォルダのアイコン、ワークスペース名（`workspaceRoot` の末尾のフォルダ名。無ければ「フォルダが不明」）、「実行中 N」。要確認のジョブがあれば「要確認 N」も添える。
  - フォルダの並び順（自動）: 要確認（`Orphaned` / `Quiet`）のジョブがあるフォルダを先に、その後はフォルダ内の最新の開始が新しい順。利用者が並べ替えたら、それを優先する（下の「並べ替え」）。
  - 同じ名前の別のフォルダ（`workspaceRoot` が違う）は別の見出しにし、見出しにマウスを乗せたら `workspaceRoot` の全体をツールチップで出す。
- **タイル**: まとまりの中で、見出しの下にカードを格子状に並べる（最大3列）。
- フォルダ内のカードの並び順（自動）: 要確認（`Orphaned` → `Quiet`）を先に、その後は開始が新しい順。利用者が並べ替えたら、それを優先する。
- **並べ替え（マウスのドラッグ＆ドロップ）**:
  - **フォルダのまとまり**は、見出しをつかんで、ほかのまとまりの前後に移せる。
  - **カード**は、同じフォルダの中でだけ移せる。別のフォルダのまとまりには落とせない（落とせない場所ではカーソルを「禁止」にする）。
  - ドラッグ中は、落とす位置に挿入の印（縦または横の線）を出す。
  - クリックとドラッグを区別する: 押してから5px以上動かしたらドラッグとし、離してもカードを開かない。動かさずに離したらクリックとして詳細を開く。
  - **フォルダの順番は設定に保存し、アプリを再起動しても保つ**（[アプリの土台 3](app-shell.md#3-設定) の `runningFolderOrder`。キーは `workspaceRoot`、無ければ `unknown:<ワークスペース名>`）。
  - **カードの順番は、本アプリが動いている間だけ保つ**（Rust 側の本アプリの状態にメモリで持つ。ウィンドウを閉じて開き直しても保つが、再起動では消える）。終わったジョブは順番から外す。
  - 並べ替えた後に**新しく現れたフォルダやカードは、並べ替えたものより前に、自動の並び順で出す**（新しいものに気づけるように）。
  - 並べ替えたものがあるときは、画面の上部に「並びを自動に戻す」を出す。押すとフォルダの順番（設定）とカードの順番（メモリ）を消す。
  - 実装には HTML5 の Drag and Drop API を使う（新しいライブラリは使わない）。**Windows では Tauri のウィンドウの作成時に `disable_drag_drop_handler()` を呼ばないと、画面の中のドラッグ＆ドロップが動かない**（Tauri が WebView2 のドラッグ＆ドロップを、ファイルのドロップを受けるために横取りするため。[アプリの土台 2](app-shell.md#2-ウィンドウの寿命)）。
- **カードの中身**（上から）:
  - 状態アイコンと**依頼の説明**（[1.2](#12-ジョブ一覧すべての左) と同じ決め方。2行まで折り返し、それ以上は「…」）。
  - 薄い文字で会話のタイトル（無ければ「名前のない会話」。1行に収まらなければ「…」）。フォルダは見出しで分かるので、カードには出さない。
  - フェーズの表示名のチップ（`Queued` は「待機中」、`Quiet` は「応答なし？」、`Orphaned` は「停止した可能性」）と、「経過時間 · 動き N前」。
    - **「動き N前」は `logModifiedAt`（ログが最後に更新された時刻）からの経過**。「N秒前」（60秒未満）、「N分前」、「N時間前」。`logModifiedAt` が無ければ出さない。
  - 等幅・薄い文字で `latestMessage` を1行（収まらなければ「…」。`Running command: ` などの決まった前置きは省き、コマンドの部分を出す）。マウスを乗せたら全文をツールチップで出す。
  - `Quiet` のカードは橙、`Orphaned` のカードは赤の枠にする。
  - 未確認のジョブ（`Orphaned` になったものなど）は、依頼の説明の前に点を付ける。
- **カードを押す（または Tab で選んで Enter）と、「すべて」に切り替えてそのジョブを詳細に出す。** 矢印キーには何も割り当てない（2026-10-11 に外した）。
- 動いているジョブが無いときは、「実行中のCodexジョブはありません」と出し、その下に**直近の完了**（終わったジョブを新しい順に3件まで、1行ずつ。押すと「すべて」で開く）を出す。動いているジョブがあるときも、カードの下に「直近の完了: <依頼の説明>（時刻） · ほか N件」を1行だけ出す（N は表示期間内に終わった件数。押すと「すべて」へ）。
- 経過時間と「動き N前」は、この画面を表示している間は**5秒ごと**に描き直す（「すべて」の画面は従来どおり30秒ごと）。
- 件数が多くても仮想スクロールは使わない（動いているジョブは多くても十数件の想定）。画面の高さを超えたら普通にスクロールする。

### 1.2 ジョブ一覧（「すべて」の左）

一覧は **会話 → 依頼（ジョブ）** の階層で見せ、**1件のジョブを1行**で出す（[ADR-0004](../adr/0004-job-context-and-history.md)、[ジョブの文脈](job-context.md)）。同じ会話のジョブが多くても長くならないよう、完了したジョブは畳む。幅は360px固定。

- 対象: 実効状態が `Queued` / `Running` / `Quiet` / `Orphaned` のジョブ全部と、それ以外で終了（無ければ作成）が設定の期間内（既定3日）のもの。
- **第1階層: 会話**（`context.sessionId` ごと）
  - 見出し: 会話のタイトル（無ければ「名前のない会話」）。その右（収まらなければ下）に件数の要約「実行中 N · 完了 N · 失敗 N」（0件の項目は省く。`Quiet` / `Orphaned` は実行中に数える。キャンセルは「キャンセル N」）。
  - 文脈が無いジョブ（`context` が `null`）は、ワークスペースごとに「会話が不明 — <ワークスペース名>」という会話としてまとめる。
  - 並び順: 実行中のジョブがある会話を先に（その中の最新の開始が新しい順）、その後は最後の活動（終了または作成）が新しい順。
  - 折りたたみ: 実行中または未確認のジョブがある会話は開く。それ以外は閉じる。利用者が開閉したら、ウィンドウを閉じるまで覚えておく。
- **第2階層: ジョブ**（同じスレッドのジョブは、最新のものだけをこの階層に出す）
  - **1行**: 状態アイコン、**依頼の説明**（`context.requester.description`。無ければ `promptHead`、それも無ければ `title`。収まらなければ「…」）、右端に状態の要約（実行中は「<フェーズの表示名> <経過時間>」をチップで、終わったものは「<状態の表示名> <終了時刻>」を薄い文字で）。未確認なら先頭に点。`kindLabel` が `rescue` 以外なら小さく出す。
  - 地続きの前回以前のジョブ（`previousJobId` をたどったもの）があれば、依頼の説明の後ろに小さく「**続き N**」（N は前回以前の件数）を出す。前回以前のジョブは一覧には出さず、詳細の「前回／次回」（[1.3](#13-詳細すべての右)）でたどる。
  - マウスを乗せたら、依頼の説明の全文、ワークスペース名、依頼文の先頭（`promptHead`）をツールチップで出す。
  - 実行中のジョブの `latestMessage` やワークスペース名は、一覧には出さない（「実行中」の画面と詳細で見る）。
  - **同じ会話・同じワークスペースのジョブが並んでも、依頼の説明で見分けられるようにする。**
- **畳み方**（会話ごと）
  - 実行中（`Queued` / `Running` / `Quiet` / `Orphaned`）・失敗・未確認のジョブは**常に出す**。
  - それ以外（完了・キャンセル）は、**新しいものから2件だけ**出し、残りは最後の1行「完了 N件を表示」（キャンセルを含むなら「完了・キャンセル N件を表示」）に畳む。押すと全部出し、その行は「畳む」になる。開閉はウィンドウを閉じるまで覚えておく。
  - 並び順: 実行中（開始が新しい順）→ 失敗・未確認（終了が新しい順）→ 完了・キャンセル（終了が新しい順）。
- 状態アイコンと表示名:

  | 実効状態 | アイコン | 表示名 |
  |---|---|---|
  | `Queued` | ○（青） | 待機中 |
  | `Running` | ●（青） | フェーズの表示名（[データソース仕様 4](data-source.md#4-phase-の値)） |
  | `Quiet` | ●（橙） | 応答なし？ |
  | `Orphaned` | ！（赤） | 停止した可能性 |
  | `Completed` | ✓（緑） | 完了 |
  | `Failed` | ✕（赤） | 失敗 |
  | `Cancelled` | －（灰） | キャンセル（`archivedNote` があれば「中断された可能性」） |
  | `Unknown` | ？（灰） | `status` の値をそのまま |

- 選んだ行が詳細に出る。↑↓キーで、見えている行（会話の見出しと「N件を表示」を除く）の間を選択が動く。←→キーで会話を閉じる・開く。
- 一覧は仮想スクロール（`@tanstack/react-virtual`）で描く。会話の見出しと「N件を表示」も1行として扱う。
- ジョブが1件も無いときは「Codexのジョブはまだありません」と、監視中の状態ルート（`health.watchedRoots`）を出す。
- 経過時間は30秒ごとに描き直す。表示の仕方はトレイと同じ（1分未満は「1分未満」、60分未満は「N分」、それ以上は「N時間M分」）。

### 1.3 詳細（「すべて」の右）

- 何も選んでいないときは「左の一覧からジョブを選んでください」。
- 地続きの前回以前のジョブは一覧に出さないので、ここの「前回／次回」でたどる。
- 見出し: **依頼の説明**（無ければ依頼文の先頭）、その下に会話のタイトル · ワークスペース名 · 種別、状態の表示名、開始時刻と経過時間（終了していれば所要時間と終了時刻）、`write` が真なら「書き込みあり」。依頼したものが入れ子なら「<parentDescription> から依頼」、会話の本体から直接なら「会話から直接依頼」と添える。
- 地続き: `previousJobId` があれば「前回: <依頼の説明>」、このジョブを前回とするジョブがあれば「次回: <依頼の説明>」を出し、押すとそのジョブに移る。
- **履歴にだけあるジョブ**（`archived`）: 上部に「codex-plugin-cc の一覧から消えたジョブです（Claude の会話が終わると消えます）。ログは表示できません。」と出し、`archivedNote` があれば添える。ログの欄は出さず、依頼文は `promptHead`（先頭200文字）だけを出す。
- 依頼の全文（`prompt`）: 折りたたみ式。最初は閉じる。
- **ログ**:
  - ログを1行の形式とブロックの形式（[データソース仕様 7](data-source.md#7-ログファイルの形式)）に分けて表示する。時刻はローカル時刻の `HH:mm:ss`。
  - `Running command:` / `Command completed:` / `Command failed:` の行は等幅。`Command failed:` は赤。
  - `Assistant message` と `Final output` のブロックは、左に色の帯を付けて目立たせ、本文は折り返して全文を出す。
  - リアルタイムで追記する。末尾にいる間は自動でスクロールし、上にスクロールしたら止める。止まっている間に追記があったら「新しいログ ↓」ボタンを出す。
  - 最初は末尾の 1MB だけを読む。それより前があれば（`truncatedBefore`）、先頭に「さらに読み込む」ボタンを出し、押すと直前の1MBを読み足す。
  - ログが長くなるので仮想スクロールで描く（行の高さが違うので、要素の高さを測る方式にする）。
- 結果: 完了・失敗・キャンセルしたら、ログの上に結果の欄を出す。`Completed` なら `summary`（`state.json` 側）と `rendered`、`Failed` / `Cancelled` なら `errorMessage`。`rendered` は等幅のまま、折り返して出す（Markdownとして描画しない）。
- 操作: 「フォルダを開く」（ワークスペース）、「ログを開く」（ログファイルを既定のアプリで開く）、「IDをコピー」（ジョブIDとthreadIdを選べる）。コピーは `navigator.clipboard` を使う。
- 詳細を表示したら `mark_seen` を呼ぶ。

### 1.4 上部のバナー

`health.lastError` があればそれを、`pluginVersion` があって `versionSupported` が偽なら「codex-plugin-cc のバージョン（X）は動作未確認です」を出す。どちらも無ければバナーごと出さない。

### 1.5 設定（⚙）

ダイアログで開く。保存したら即座に反映する。

| 項目 | 入力 | 範囲 |
|---|---|---|
| 通知（全体） | スイッチ | |
| 通知のきっかけ（開始・完了・失敗・停止した可能性・応答なし） | スイッチ×5 | |
| 応答なしと判定するまでの分数 | 数値 | 1〜120 |
| 一覧に出す終わったジョブの期間（日） | 数値 | 1〜30 |
| 履歴の保存期間（日） | 数値 | 1〜90。一覧の期間以上 |
| 追加で監視する状態ルート | 1行に1つのテキスト | 絶対パスだけ。空行は無視 |
| Windows起動時に起動 | スイッチ | |

範囲外の値は保存できないようにし、その欄の下に理由を出す。Rust側でも同じ範囲を検証し、外れていたらエラーを返す。

## 2. コマンド（画面 → Rust）

| 名前 | 引数 | 戻り値 | 内容 |
|---|---|---|---|
| `get_snapshot` | なし | `UiSnapshot` | `{ jobs: JobSummary[], unseen: string[], health: Health, settings: Settings, cardOrder: Record<string, string[]> }`（`cardOrder` はフォルダのキーごとのカードの順番） |
| `get_job` | `id` | `JobDetail \| null` | 監視コアの `job_detail` |
| `read_log` | `id`, `from: number \| null` | `LogChunk \| null` | 監視コアの `read_log`。`from` が `null` なら末尾から1MB |
| `watch_log` | `id: string \| null` | なし | ログを購読するジョブを**1つだけ**指定する。前の購読は外す。`null` で外す |
| `mark_seen` | `id` | なし | 未確認から外し、トレイを更新し、`unseen-changed` を送る |
| `open_path` | `kind: "workspace" \| "log"`, `id` | なし | ジョブの `workspaceRoot` のフォルダ、またはログファイルを開く（`tauri-plugin-opener`） |
| `set_settings` | `Settings` | `Settings` | 検証して保存し、反映する（[アプリの土台 3](app-shell.md#3-設定)） |
| `set_card_order` | `folderKey: string`, `ids: string[]` | なし | 実行中の画面で、そのフォルダのカードの順番を本アプリの状態（メモリ）に記録する。空の配列で消す |
| `reset_running_order` | なし | `Settings` | フォルダの順番（設定の `runningFolderOrder`）とカードの順番（メモリ）を消す |
| `take_pending_focus` | なし | `string \| null` | トレイから開かれたときに表示すべきジョブのIDを取り出す（取り出したら消える） |

- コマンドの中身は薄くし、処理は監視コアと本アプリの状態（`state.rs`）の関数に置く。
- `open_path` は、**本アプリが把握しているジョブのパスだけ**を開く。画面から任意のパスを受け取らない。ログファイルは `logFile` ではなく、状態ディレクトリと `id` から組み立てたパスを使う（監視コアと同じ）。
- エラーは日本語の文字列で返し、画面は詳細の上部に出す。
- ウィンドウが破棄されたら（`WindowEvent::Destroyed`）、ログの購読を外す。

## 3. イベント（Rust → 画面）

| 名前 | 内容 |
|---|---|
| `monitor-event` | 監視コアの `MonitorEvent` をそのまま送る（`type` で種類を見分ける。実装済み） |
| `unseen-changed` | `string[]`。未確認のIDの集合が変わったときに全体を送る |
| `settings-changed` | `Settings`。トレイのメニューなど、画面の外で設定が変わったとき |
| `focus-job` | `{ id }`。ウィンドウがすでに開いているときに、トレイのメニューからジョブが選ばれたら送る |

### トレイからジョブを指定して開く流れ

ウィンドウは開くたびに作り直されるので、画面の準備ができる前に送ったイベントは届かない。そこで次のようにする。

1. トレイのメニューでジョブが選ばれたら、本アプリの状態に「表示待ちのジョブ」としてIDを記録する。
2. ウィンドウがすでに開いていれば、`focus-job` を送り、記録を消す。
3. 新しく作ったウィンドウでは、画面が起動時に `take_pending_focus` を呼んで取り出し、そのジョブを選ぶ。
4. どちらの場合も、画面は**「すべて」に切り替えて**そのジョブを詳細に出す（[1](#1-画面の構成)）。表示待ちのジョブが無ければ「実行中」から始める。

画面は起動時に、`get_snapshot` → `take_pending_focus` の順に呼び、その後でイベントの受け付けを始める。`get_snapshot` とイベントの間で取りこぼしが出ないよう、受け付けを始めた直後にもう一度 `get_snapshot` を呼んで置き換える。

## 4. 画面の作り

```
src/
├─ main.tsx              起動
├─ App.tsx               全体の配置
├─ api.ts                コマンドとイベントの型付きの呼び出し口（invoke / listen はここだけで使う）
├─ bindings/             ts-rs が生成した型（手で編集しない）
├─ model/
│  ├─ format.ts          フェーズ・実効状態の表示名、経過時間、時刻の表示（純粋な関数）
│  ├─ logParse.ts        ログの解析（1行・ブロック・コマンド行の判定。純粋な関数）
│  ├─ jobList.ts         「すべて」の一覧のグループ分け、並べ替え、畳み方、絞り込み（純粋な関数）
│  ├─ running.ts        「実行中」の画面のカードの並び、直近の完了、「動き N前」の表示（純粋な関数）
│  └─ store.ts           スナップショットとイベントから画面の状態を作る reducer（純粋な関数）
├─ components/           ViewSwitch / RunningView / RunningCard / JobList / JobRow / JobDetail / LogView / Banner / SettingsDialog など
└─ styles.css            CSS変数で配色を定義し、ダークテーマは prefers-color-scheme で切り替える
```

- 状態管理のライブラリは使わず、React の `useReducer` と `store.ts` の reducer で持つ。今どちらの画面か（`view: "running" | "all"`）も reducer の状態に持つ。
- UIの部品ライブラリは使わない（バンドルを小さく保つ）。
- フェーズの表示名と経過時間の表示は、Rust側（`presentation.rs`）と同じ規則にする。両方のテストで同じ例を確かめる。

## 5. 型

画面に渡す型は Rust 側で定義し、`ts-rs` で TypeScript の型を生成する。手で二重に書かない。

- 生成先は `src/bindings/`（`src-tauri/.cargo/config.toml` の `TS_RS_EXPORT_DIR` で指定済み）。
- 生成は `npm run bindings`（`ts` 機能付きで `export_bindings` のテストを動かす）。**生成した型はリポジトリに入れる**（Rustをビルドしなくても画面をビルドできるように）。
- 対象: 監視コアの `JobSummary` / `JobDetail` / `EffectiveState` / `LogChunk` / `Health` / `MonitorEvent`、本アプリの `UiSnapshot` / `Settings`（とその中の型）。各型に `#[cfg_attr(feature = "ts", derive(ts_rs::TS), ts(export))]` を付ける。
- **`u64` / `i64` のフィールドには `#[cfg_attr(feature = "ts", ts(type = "number"))]` を付ける。** ts-rs は既定で `bigint` にするが、JSONでは数値として届くため。ログのバイト位置などは 2^53 を超えない。
- 日時（`chrono::DateTime<Utc>`）は文字列（ISO 8601）として届く。

## 6. テスト

- Vitest で `model/` の純粋な関数を試す。最低限:
  - `format.ts`: フェーズ・実効状態の表示名（知らない値を含む）、経過時間の境目（59秒・60分）
  - `logParse.ts`: 1行の形式、ブロックの形式（空行・複数行の本文）、コマンド行の判定、途中で切れた最後の行
  - `jobList.ts`: 会話ごとのまとめ（文脈が無いジョブの「会話が不明 — <ワークスペース>」を含む）、会話の見出しの件数の要約、会話とジョブの並び順、**畳み方**（実行中・失敗・未確認は常に出し、完了・キャンセルは新しい2件だけ出して残りを「N件を表示」にまとめる。開いたときは全部出る）、地続きのジョブを最新の1件にまとめて「続き N」の N を数えること（3件の連鎖で N=2）、表示期間、ワークスペースの絞り込み、折りたたみの既定、**同じ会話・同じワークスペースの実行中ジョブが2件あるとき、依頼の説明で別の行として出ること**、依頼の説明が無いときの代わり（`promptHead` → `title`）
  - `running.ts`: 利用者の並べ替えの反映（保存したフォルダの順番とカードの順番を優先し、新しく現れたフォルダ・カードは先頭に自動の順で出す。終わったジョブや無くなったフォルダは順番から無視する）、ドロップ位置からの新しい順番の計算（同じフォルダの中だけ。別のフォルダへのドロップは拒む）、まとまりの列数（`min(枚数, 3)`）、動いているジョブだけを選ぶこと、**フォルダごとの分け方**（同じ名前で `workspaceRoot` が違うものは別、`workspaceRoot` が無いもの、見出しの「実行中 N」「要確認 N」）、フォルダの並び順（要確認のあるフォルダが先）、フォルダ内の並び順（`Orphaned` → `Quiet` → 開始が新しい順）、`latestMessage` の前置きの省略、直近の完了（3件まで、新しい順）と「ほか N件」の数、「動き N前」の表示の境目（59秒・60分・`logModifiedAt` が無いとき）
  - `store.ts`: 画面の切り替え（起動時は「実行中」、表示待ちのジョブや `focus-job` があれば「すべて」に切り替わってそのジョブが選ばれる、カードを選ぶと「すべて」に切り替わる）、`monitor-event` の各種類の反映（`JobsChanged` の追加・削除、選択中のジョブが削除されたとき）、`unseen-changed`、`LogAppended` の連結（`start` が手元の末尾と一致しないときは読み直す）
- Rust 側: カードの順番の記録・終わったジョブの除外・リセット、`runningFolderOrder` の保存と読み込み（古い設定ファイルに無くても動く）、表示待ちのジョブの記録と取り出し、`watch_log` の置き換え、`open_path` が把握していないIDを拒むこと、設定の検証（範囲外の値）を単体テストする。
- 画面の見た目と操作は、手動の受け入れ確認で確かめる（[DESIGN.md 7](../DESIGN.md#7-段階1の受け入れ基準)）。
