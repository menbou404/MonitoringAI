# ADR-0004: Claude Code の会話記録からジョブの文脈を求め、独自の履歴を持つ

- 状態: 承認
- 日付: 2026-10-09

## 背景

段階1の画面を実際に使ったところ、「どのようなタスクで呼び出されたジョブなのか」がわかりにくい、という指摘があった。Codex のジョブは、同じワークスペースでも別のワークスペースでも複数が同時に動き、同じ会話から続けて依頼されたり、並行したサブエージェントから依頼されたりする。ワークスペース名と依頼文の先頭だけでは見分けにくい。

調べたところ、次のことがわかった。

1. codex-plugin-cc の状態ファイルには、依頼元の会話の `sessionId` と、Codex 側のスレッドの `threadId` があるが、**会話の名前や依頼の目的はない**。
2. Claude Code の会話記録には、会話のタイトルと、サブエージェントごとの説明（Claude が書いた依頼の目的）が残っている。サブエージェントの記録とジョブは、ジョブIDか、呼び出しの時刻と依頼文で照合できる（[会話記録の仕様](../design/claude-transcripts.md)）。
3. **codex-plugin-cc は、Claude の会話が終わると、その会話のジョブを状態ファイルからログごと削除する。** 会話を閉じると、一覧から履歴が消える。

## 検討した選択肢

### 文脈の情報源

| 選択肢 | 得られるもの | 問題 |
|---|---|---|
| **A. Claude Code の会話記録を読む** | 会話のタイトル、依頼の説明、入れ子の関係 | 非公開の形式。会話の全文を含むファイルを読むことになる |
| B. Claude Code のフックで、依頼のたびに情報を書き出す | 必要な情報だけを確実に得られる | 利用者の設定ファイルを書き換える必要がある。フックの入力に「サブエージェントの説明」があるとは限らない |
| C. 状態ファイルの情報だけで工夫する（ワークスペース・依頼文・`threadId`） | 地続きのジョブはわかる | 会話や依頼の目的はわからない |

### 履歴

| 選択肢 | 問題 |
|---|---|
| **D. 概要と結果だけを独自に保存する** | 会話が終わった後はログを見られない |
| E. ログも含めて保存する | 容量が増える。依頼の内容を含むログが手元にたまる |
| F. 保存しない | 会話を閉じると一覧から消える |

## 決定

- **A を使う。** 読み取り専用で、取り出すのは会話のタイトルと、サブエージェントの説明・種類・深さだけとする。照合のためにほかの部分も読むが、保存・表示・記録はしない。C（`threadId` による地続きの判定）も併用する。
- **D を採る。** ログは保存しない。保存期間は既定30日。
- 一覧は「会話 → 依頼 → ジョブ（地続きのものはつなげる）」の階層で見せる（利用者が選択）。

## 理由

- B は利用者の設定を書き換える必要があり、[ADR-0002](0002-data-source.md) で避けた方針と矛盾する。A は読むだけで済む。
- 依頼の説明は Claude 自身が書く短い文で、ジョブの目的を最もよく表す。
- D は、利用者が「概要＋結果」を選んだことによる。履歴の目的は「何をして、どうなったか」を後から見ることで、ログの全文までは要らない。

## 結果として受け入れること

- **非公開の形式への依存がもう1つ増える。** 会話記録の形式が変わると、文脈が求まらなくなる。その場合も監視そのものは動くよう、文脈が求まらないことはエラーにせず、表示を「会話が不明」に落とす。
- 会話の全文を含むファイルを読む。取り出す項目を限定し、ほかの内容は保存・表示・記録しないことを、設計書とテストで担保する。
- 会話が終わった後のジョブは、ログを見られない（画面にその旨を出す）。
- 状態ファイルから消えた理由（会話の終了か、51件を超えたためか）は区別できない。実行中に消えたものは「中断された可能性」として扱う。
